# 2026-11-17 执行过程可见性改为消费方主动拉取

## 背景

- 2026-11-14 完成 ACP 过程信息调研（`docs/history/works/2026-11-14-acp-progress-feedback/`）：DSH 在工具级实时推送，client 收到后只落本地；跨边界只有开始与结束。
- 当日用户确认按「5s 回报 + 模式 C（独立进度端点）」做设计；设计稿列出 C1–C6 待确认，随后未进入实现。
- 2026-11-17，client 只读观测面 v1（O-01–O-11）落地，调度器侧适配器与 6 个产品 API 完成；UI 会话/文件视图尚未接入。
- 用户 2026-11-17 判断：5s 模式 C 暂不实施；UI 主动发起查询/拉取观测面，比 client 被动推送更全面。

## 决策

1. **5s 进度推送（模式 C）暂不实施**。不新增 `POST /tasks/{taskId}/progress`、`poll` 进度字段、`progress-v1` 能力协商或调度器 `ProgressRegistry`。原设计稿 C1–C6 不再是待确认项。
2. **执行期过程信息的唯一来源是 client 只读观测面**（O-01–O-11）。消费方主动拉取或订阅，client 不主动推送进度。
3. **UI 主动发起，经调度器产品 API/BFF 拉取**（API-48–53）；UI 不直连 client，沿用 2026-11-17 交接边界与鉴权。若将来要直连，需重新定级（网络可达、token、暴露面）。
4. **client 不新增进度端点/字段**；`lastEventAt` 暂不补——拉取模型下最近活动可由事件 `ts` 推导。若 UI 需要低成本的一眼可见字段，另行定级再开。
5. **内容口径以 `client-observability-v1` 为准**：preview 不返回 prompt/推理/工具 I/O 全文；富事件 `O-11` 含 prompt/message/thought/工具 I/O（≤16 KiB），按该契约的保留与安全规则执行。
6. 原 5s 设计（`design-progress-5s.md`）与调研结论保留为历史分析，**不作为现行设计依据**；其端点编号不预留。

## 理由

- **更全面**：拉取可按需取事件、历史、raw 与文件，不受 5s 节流、字段裁剪与"只保留最新快照"限制。
- **更简单**：client 不必新增采样循环、`seq`、失败重试与能力协商；观测面已有实现与测试。
- **边界已具备**：观测面只读、默认 loopback、非 loopback 必须 token；调度器适配器与产品 API 已通。
- **失败隔离不变**：拉取失败只影响观测，不影响任务执行与结果上报。
- **聚合位置可后置**：阶段、当前工具、最近活动、上下文水位由消费方按事件聚合；先不为未定的 UI 形态固化协议字段。

## 影响

- 原调研的阶段 0/1 不再作为实现计划；阶段 2（观测面）成为唯一路径。
- UI 承担聚合与渲染；节点卡片是否显示摘要由 UI 项目决定，数据仍来自产品 API。
- 观测面同时服务执行期与事后排障；保留、安全、内容上限按 `client-observability-v1` 执行。
- 文档同步：`architecture.md` 增补拉取面；`CMP-observability` 删除进度事件；`CMP-observer` 明确消费方主动拉取。

## 备选与否决

| 方案 | 结论 | 理由 |
|---|---|---|
| 5s 推送（模式 C） | 暂不实施 | 新增跨仓库契约与调度器内存存储；收益可由拉取覆盖 |
| `poll` 内嵌 `progress` | 否决 | 受 30s 挂起上限约束，且要继续裁剪字段 |
| 中途上传 `P-04` 快照 | 否决 | 体积放大、全文暴露，UI 需自行解析 |
| UI 直连 client | 暂不采用 | 需要额外网络/鉴权/暴露面决策；BFF 已够用 |

## 未决

1. UI 会话 Tab 的聚合与呈现规则（外部项目）。
2. 节点卡片是否需要"一眼可见"摘要；若需要，优先在调度器产品 API 聚合，不新增 client 字段。
3. `lastEventAt` 的重开条件：UI 无法从事件推导，或轮询成本不可接受。
4. 观测面工序（`docs/works/2026-11-06-observability-http/`）的归档与 `OQ-022` 旧口径清理。
5. 调度器仓库同步：本决策只在 client 仓库落档；需调度器侧在自身决策/设计中记明 `P-06`/`ProgressSnapshot` 不做，避免两仓库预期分叉。
