# REQ-0002：节点执行的稳定性与可靠性

**类型**：quality

## 1. 场景叙述

调度器把节点交给 client 后，即使网络抖动、重复投递、进程崩溃、取消或技能刷新失败，节点结果仍然一致、可恢复、无残留；操作员能从本地日志和 `doctor` 定位失败阶段与原因。

结果是：同一节点不会因为传输/进程故障被重复执行或悄悄丢失结果；中断后机器保持干净，等调度器重新下发即可继续。

## 2. 价值

不做的后果不是「偶发失败」，而是执行面无法被信任：

- **重复执行**：同一节点跑两遍，产物覆盖或重复，调度器无法判定哪次有效。
- **结果丢失**：prompt 完成但上报失败，节点永远停在「执行中」。
- **孤儿进程**：dsh/工具子进程残留，占资源、继续写工作区、污染下一次尝试。
- **技能串味/半套**：模型看到不属于当前节点的能力，或刷新失败后带病执行。
- **跨 profile 会话暴露**：ACP 会话进入 desktop/web 的 `session/list`，用户私人历史反向进入 client。
- **不可诊断**：失败只有一句「exit 1」，无法定位阶段与原因。

## 3. 非目标

- 不做高可用、多机迁移、跨 client 恢复；实例粘性不变。
- 不做性能/SLA/容量规划；阈值留给 M1 与组件规格。
- 不改 DSH/ACP 协议，不做 DSH 源码改造。
- 不做编排决策（下一节点、评审、fan-out 拆分、回退）。
- 不做多实例 per-instance home 派生与回收；本卡只约束单 home 下的隔离，多实例另立需求（OQ-009）。
- 不做 UI、产物上传、完整会话记录跨边界。
- 不在本卡定结果大小/日志保留/并发上限的具体数值（M1）。
